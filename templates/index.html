Cryptographic Mechanics: Diffie–Hellman MITM

1. Normal Diffie–Hellman Key Exchange

Alice and Bob agree on public parameters modulus p and generator g. Alice chooses private key a, computes public key A = g^a mod p. Bob chooses private key b, computes public key B = g^b mod p. Both compute the identical secret K = g^(ab) mod p.

2. Unauthenticated Key Substitution (MITM)

Standard Diffie–Hellman does not authenticate identity. Mallory sits on the network path, intercepts Alice's public key A, and sends Alice her own key M_A. She also intercepts Bob's public key B and sends Bob M_B.

3. Dual Secret Establishment & Bi-Directional Interception

Alice and Mallory compute key K_AM. Bob and Mallory compute key K_MB. Because Mallory holds decryption keys for both channels, she can auto-decrypt, inspect, and modify traffic in both directions (Alice → Bob and Bob → Alice).

4. AES-GCM Integrity vs Authentication

AES-GCM guarantees payload confidentiality and integrity within an individual channel key. However, because Mallory possesses key K_AM and key K_MB, she decrypts messages on one channel and re-encrypts under the other channel key. Both endpoints' AES-GCM integrity checks pass successfully!
